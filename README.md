# Pour Guide

핸드드립 레시피를 직접 만들고, 추출 중 언제 몇 그램을 붓고 어떤 행동을 해야 하는지 실시간으로 안내하는 웹앱입니다. GitHub Pages에서 동작하며 별도 계정이나 서버가 필요 없습니다.

## 기능

- **순차 레시피 편집**: 단계별 시간, 추가 물량, 붓기·기다리기·스월링·스티어링을 입력합니다.
- **단계별 유량 설정**: 붓기 단계마다 초당 그램(g/s)을 지정할 수 있습니다. 비워 두면 추가 물량÷시간으로 자동 계산하며, 지정 유량으로 단계 시간 안에 붓지 못하면 필요한 최소 시간을 알려 주고 저장을 막습니다.
- **실시간 가이드**: 실제 경과 시간 기준으로 현재 단계, 누적 목표 물량, 추가로 부을 양, 남은 시간과 다음 단계를 표시합니다.
- **두 개의 저울 목표**: 추출 화면 왼쪽에는 이번 단계가 끝날 때의 **최종 누적 목표**, 오른쪽에는 설정 유량으로 증가하는 **지금 목표**를 나란히 표시합니다. 목표에 먼저 도달하면 남은 시간 동안 그 무게를 유지합니다.
- **정확한 일시정지와 재개**: 탭이 백그라운드로 밀려도 벽시계 시간으로 보정합니다.
- **레시피 보관**: 브라우저 로컬 저장, JSON 내보내기·가져오기, 예제 레시피 3종.
- **모바일 우선 화면**: 큰 타이머와 물량, 추출 중에도 읽기 쉬운 단계 카드, 키보드 접근성과 모션 감소 지원. 터치 기기와 좁은 화면에서는 입력창·선택창의 글꼴을 16px로 유지해 입력 시 자동 확대를 방지하며, 사용자의 핀치 확대는 허용합니다.
- **적응형 디자인**: 시스템 글꼴과 의미 기반 색상 토큰을 사용하며 고대비, 투명도·모션 감소 설정에 맞춰 표시합니다. 상단의 테마 버튼은 `자동 → 라이트 → 다크` 순서로 전환되고 기본값은 `자동`입니다. 자동은 운영체제 테마를 따라가며, 라이트·다크를 직접 고르면 운영체제 설정과 무관하게 유지되고 새로고침 후에도 복원됩니다. 모바일에서는 레시피 목록을 필요할 때만 펼쳐 타이머를 먼저 보여 주고, 편집기는 화면 높이에 맞춘 시트로 엽니다.
- **소리 알림**: 사용자가 켠 경우에만 단계 전환음이 납니다. 음소거 해제 시 확인음이 울리고 이후 단계 알림이 다시 재생됩니다. 브라우저가 소리를 막으면 화면에 안내합니다.
- **자동 새 버전 확인**: 배포 버전을 주기적으로 확인해 오래된 화면을 계속 쓰지 않습니다. 추출·편집·전체화면 중에는 방해하지 않고, 준비 상태로 돌아오면 새 화면을 적용합니다. 추출 완료 화면에서는 결과를 읽는 동안 자동으로 바뀌지 않고 `지금 적용`으로 직접 넘어갑니다.
- **전체화면 추출**: 데스크톱과 모바일에서 추출 패널을 화면 전체로 펼칩니다. 브라우저 전체화면 API가 없는 환경에서는 같은 크기의 대체 전체화면을 사용하며, 두 경우 모두 Escape와 `전체화면 종료`로 돌아옵니다.

물량은 **각 단계에서 추가로 붓는 양**입니다. 시작 시각은 단계 시간을 누적하여 자동 계산되므로 별도로 입력할 필요가 없습니다.

추출 화면의 두 목표는 모두 **추출 시작 전에 영점을 맞춘 저울의 누적 무게**입니다. 예를 들어 60g을 부은 뒤 120g 단계라면 왼쪽 최종 목표는 180g, 오른쪽 지금 목표는 60g에서 180g으로 유량에 따라 증가합니다.

## 시작하기

```bash
npm install
npm run dev
```

개발 서버는 `http://127.0.0.1:5173/pour-guide/`에서 열립니다.

```bash
npm test        # 계산·타이머 동작 검증
npm run build   # 타입 검사 + 프로덕션 빌드
npm run preview # 빌드 결과 로컬 확인
```

## GitHub Pages 배포

`.github/workflows/deploy.yml`은 `main` 브랜치에 푸시하면 테스트, 빌드, Pages 배포를 실행합니다. 저장소 **Settings → Pages → Source**는 **GitHub Actions**여야 합니다.

공개 주소: <https://licht0182.github.io/pour-guide/>

Vite의 `base`는 저장소 하위 경로(`/pour-guide/`)에 맞춰 설정되어 있습니다. 저장소 이름을 바꾸면 `vite.config.ts`의 `base`도 함께 바꿉니다.

빌드할 때마다 `dist/version.json`에 버전이 기록되고, 앱은 이 파일을 1분마다 그리고 탭이 다시 보일 때 확인합니다. GitHub Pages는 문서를 브라우저에 약 10분간 캐시하므로, 앱은 새 버전을 확인하면 현재 URL에 버전 쿼리를 붙여 브라우저 캐시를 우회한 새 문서를 요청합니다(쿼리마다 다른 캐시 항목). 배포 시 Pages의 CDN은 갱신되므로, 추출·편집·전체화면 중이면 그 작업이 끝난 뒤 새 화면으로 넘어갑니다. 다만 이 확인 기능이 배포되기 전에 열어 둔 탭에는 확인 코드가 없으므로 한 번은 직접 새로 고쳐야 합니다. 레시피는 `localStorage`에 그대로 남습니다.

## 데이터와 개인정보

레시피는 기본적으로 브라우저 `localStorage`에 저장됩니다. Google Drive 자동 동기화를 연결하거나 수동 백업의 저장 버튼을 누르면 해당 Google 계정의 앱 전용 데이터 공간으로 전송됩니다. Drive 기능이 설정된 경우 Google 로그인 스크립트를 불러오며 별도 분석 도구는 사용하지 않습니다. 브라우저 저장 공간을 비우면 로컬 레시피도 삭제되므로 중요한 레시피는 Drive 또는 JSON으로 보관하세요.

## Google Drive 클라우드 동기화

로그인에 성공했는데 연결 확인이 실패하면 [Drive API 설정](https://console.cloud.google.com/apis/library/drive.googleapis.com?project=pour-guide)의 상태가 **사용 설정됨**인지 확인합니다. API 비활성화(`SERVICE_DISABLED`), 계정 권한 누락, 조직 정책, 요청 한도 초과는 앱에서 서로 다른 안내로 표시됩니다. API를 켠 뒤에는 잠시 후 **지금 동기화** 또는 **연결 확인**으로 다시 시도할 수 있으며 앱 재배포는 필요하지 않습니다.

Pages 빌드는 제공된 웹 클라이언트 ID `13512728967-g0g2e77gjmlrgu626gpsp8s6q5rr59m3.apps.googleusercontent.com`를 기본으로 사용합니다. 아래 Actions 변수를 설정하면 해당 값으로 변경할 수 있습니다. 로컬 개발은 `.env.local` 설정이 필요합니다. 개발 원본에는 실제 사용 중인 `http://127.0.0.1:5173`도 등록하세요.

1. Google Cloud 프로젝트에서 **Google Drive API**를 활성화하고 OAuth 동의 화면을 설정합니다. 테스트 모드라면 사용할 계정을 테스트 사용자로 등록합니다.
2. **웹 애플리케이션** OAuth 클라이언트를 만들고 승인된 JavaScript 원본에 개발 서버 원본(예: `http://localhost:5173`)과 배포 원본(`https://licht0182.github.io`)을 등록합니다. 원본에는 `/pour-guide/` 경로를 붙이지 않습니다.
3. 로컬에서는 `.env.example`을 `.env.local`로 복사하고 클라이언트 ID를 입력합니다. GitHub Pages에서는 저장소 Actions 변수 **VITE_GOOGLE_CLIENT_ID**를 설정하고 배포 워크플로를 다시 실행합니다. 클라이언트 ID는 공개 설정이며 클라이언트 비밀키는 사용하지 않습니다.
4. 앱 보관함에서 **Google Drive 연결**을 눌러 승인합니다. 최초 연결 시 현재 브라우저의 레시피와 Drive의 레시피가 병합됩니다. 공유 브라우저에서 계정을 변경하면 현재 로컬 레시피도 새 계정에 병합됩니다.

`drive.appdata` 권한만 요청하며 Drive의 숨겨진 앱 전용 공간에 저장합니다. 일반 Drive 파일 목록에는 표시되지 않습니다. 레시피 변경 후 1.2초, 앱이 열려 있는 동안 60초마다, 온라인 복귀와 화면 복귀 시 동기화합니다. 추출/편집 중에는 원격 적용을 미룹니다. 앱이 닫힌 상태에서는 동기화하지 않습니다. 오프라인 변경은 브라우저에 보관하고 다음 연결 시 반영합니다.

유효한 액세스 토큰은 만료 시각·OAuth 클라이언트 ID와 함께 이 브라우저/웹앱의 `localStorage`에 보관하고 `sessionStorage`에도 복사합니다. 모바일에서 탭 저장소가 초기화되거나 새 탭으로 열리더라도 기기 저장소에서 복원해 자동 동기화를 재개합니다. 기존 탭 전용 형식의 유효한 인증은 자동 이전합니다. 저장은 각 저장소에서 독립적으로 시도하고 다시 읽어 실제 저장 여부를 확인합니다. 기기 저장소가 차단되면 탭 안의 임시 연결은 허용하면서 앱 재실행 후 유지되지 않을 수 있다는 안내를 표시합니다.

자동 동기화 사용 설정과 마지막 저장 검증 기록도 이 기기에 기억합니다. 만료된 토큰과 이전 클라이언트의 토큰은 재사용하지 않으며, 인증 만료 시 설정을 유지한 채 재연결을 안내합니다. Google 토큰은 수명이 제한되므로 영구 로그인을 제공하는 것은 아닙니다. 연결 해제는 두 저장소의 해당 연결·설정·확인 기록을 지우고 Google 권한을 철회하며 레시피를 삭제하지 않습니다. Safari와 다른 브라우저 또는 다른 웹앱 저장 공간은 서로 독립적일 수 있습니다.

자동 동기화가 업로드한 파일을 반환된 파일 ID로 다시 다운로드하여 레시피·변경 버전·삭제 기록이 모두 일치하는지 확인한 뒤에만 저장을 검증한 것으로 표시합니다. 업로드할 변경이 없다면 기존 Drive 데이터를 읽어 로컬 내용과 일치하는지 확인합니다. **Drive 저장·다시 읽기 확인**에는 검증한 레시피 수와 확인 시각을 표시합니다. 이 기록은 과거 확인 결과이며, 새 변경 사항은 별도로 동기화 대기·실패·완료 상태로 안내합니다.

레시피별 변경 버전과 삭제 기록을 병합합니다. 동일 레시피의 동시 변경은 버전 시각이 최신인 변경을 채택하므로 기기의 시계를 정확히 맞춰 주세요. 서로 다른 레시피 변경은 모두 유지됩니다. 동시 업로드의 덮어쓰기를 방지하기 위해 변경 시 불변 스냅샷을 추가합니다. 스냅샷은 자동 삭제하지 않으므로 사용량에 따라 Drive 저장 공간과 초기 동기화 시간이 증가할 수 있습니다. 손상되거나 지원하지 않는 원격 데이터는 덮어쓰지 않고 오류를 표시합니다.

## 수동 Drive 백업과 복원

자동 동기화와 수동 백업에는 각각 연결 상태와 최근 확인 시간이 표시됩니다. **자동 동기화 연결 확인** 또는 **백업 연결 확인**을 누르면 현재 토큰으로 실제 Drive 앱 저장 공간 목록을 요청합니다. 요청이 성공한 경우에만 **Drive 연결 확인됨**으로 표시하며, 레시피를 업로드·변경하지 않습니다. 실패하면 실패 상태와 오류를 표시하고, 권한 만료 시 다시 연결할 수 있습니다. 로그인 승인만으로 Drive 접근을 확인한 것으로 표시하지 않습니다. 이 확인은 Drive 접근 검사이며 저장·복원 전체 과정의 검사는 아닙니다.

자동 동기화와 별도로 **수동 Drive 백업 → Google 계정 연결 → Drive에 저장**을 사용하면 현재 보관함 전체를 새 백업으로 남깁니다. 연결만으로 업로드하지 않습니다. 최근 20개 백업에서 하나를 선택해 가져올 수 있습니다. 백업은 일반 Drive 파일 목록에 보이지 않는 앱 전용 공간에 저장되며 `drive.appdata` 권한만 요청합니다.

가져올 때 현재 레시피는 유지합니다. 내용이 같은 레시피는 건너뛰고 같은 ID에 다른 내용이 있으면 새 ID로 추가합니다. 백업 전체가 유효할 때만 적용하며 최대 5MB·1,000개 레시피를 지원합니다. 추출·편집·자동 동기화 작업 중에는 가져오기를 제한합니다. 자동 동기화가 연결된 상태에서 복원한 레시피는 이후 자동 동기화에도 반영됩니다. 두 연결에서 서로 다른 계정을 선택하면 로컬 레시피가 각 계정으로 전송될 수 있으므로 같은 계정 사용을 권장합니다.

수동 백업의 유효한 토큰과 저장 검증 기록도 기기 저장소에서 복원하며, 새로고침 후 Drive 백업 목록을 다시 조회합니다. 백업 저장 역시 업로드한 파일을 다시 읽어 전체 내용이 일치한 뒤에만 확인 메시지를 표시합니다. Google 인증이 실제로 만료되거나 저장 공간을 삭제한 경우에는 다시 연결해야 합니다. **이 기기 연결 해제**는 두 저장소의 수동 백업 연결·설정·확인 기록을 지우고 Google 계정 권한이나 백업은 삭제하지 않습니다. 자동 동기화의 **연결 해제**는 Google 권한을 철회하므로 수동 백업도 재인증이 필요할 수 있습니다.
